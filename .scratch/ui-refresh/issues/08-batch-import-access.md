# 08: 批量导入、映射与接入管理

**What to build:** 用户能清楚完成现有批量文件导入，查看批次结果、定位失败项并重导；有权限人员能维护映射及外部接入配置。

**Blocked by:** 01 工作台框架与事件查询样板

**Status:** done

- [x] 文件选择、来源映射、批次状态、成功与失败结果、失败重导及凭据相关界面组织清晰。
- [x] CSV、Excel、映射、别名和模拟外部接入相关现有 UI 流程保持有效；不增加新的接入渠道或公开敏感信息。
- [x] 规则发布页面和角色可见性保持有效；按共同要求验证。

## 共同边界与验收

- 覆盖登录页和现有全部九个业务模块，保留业务规则、角色权限、接口、数据口径与功能入口。
- 每项交付都能通过真实账号和现有接口独立演示对应流程，包含相关表单、列表、弹窗或抽屉及反馈状态的完整体验；无需为 UI 改动新增数据库或接口工作。
- 统一墨绿主色、浅灰背景、白色卡片、字体层次、圆角、边框及克制的阴影，采用均衡办公信息密度。
- 以 1440×900、1280×800 桌面及 390×844 窄屏作为布局检查样本；窄屏导航可访问、操作不被遮挡，宽表格在容器内横向滚动。
- 每项完成时运行类型检查、构建和相关既有行为测试，记录实际结果及代表性截图；必要时补充布局或交互回归检查，不编写只复述 CSS 的测试。
- 各任务同步验证权限、加载、空数据、错误提示，以及长文本和适用的表单校验；不得用静态展示替代现有真实交互。
- 第一项建立可增量采用的公共视觉约定，并先在事件查询链路落地；后续页面逐步迁移，未迁移页面仍可使用。不单设只能交付样式文件的基础任务。
