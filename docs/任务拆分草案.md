# 任务拆分草案

来源：已确认的项目规格说明书。状态：待用户审阅，尚未发布逐项任务。

当前没有应用代码，无需先做旧代码重构。建议拆为 32 个纵向任务；每项随交付包含必要的数据持久化、业务 API、可操作界面及行为验证，不按数据库、后端、前端分别立横向任务。

每项完成时更新相应启动、操作或接口说明；原始记录和审计写入随对应业务实现，不推迟到最后补做。最终交付任务只做整体验证与打包，不承接遗漏的基本功能。

依赖仅列直接前置，包含的间接依赖不重复列出。没有前置的任务可立即开始；ready-for-agent 不代表可以无视阻塞关系开工。新增接入渠道均使用已有标准化与后续处理入口，不另建不同的匹配、去重或风险链路。

当前无远程 tracker。建议确认拆分后，以本地 Markdown 跟踪：一项任务一个文件，保存于 `.scratch/social-governance-risk/issues/`，状态为 `ready-for-agent`。本草案不代表已配置 tracker，不创建项目级代理指令文件。

测试入口建议沿用规格：公开业务 API 配真实 MySQL 集成验证，辅以关键浏览器流程；本次拆分若获确认，按此落实各项行为验收。

## 01 — 登录后查看权限内事件列表

**交付行为：** 启动真实前后端与 MySQL，用预置账号登录、退出并查看权限内事件列表。

**前置依赖：** 无，可立即开始。

- [ ] 本机和最小 Compose 环境均能启动，数据重启后保留。
- [ ] 中心、普通部门及未登录请求的列表与详情访问范围正确；保留既有事件主表字段。
- [ ] 通过页面与真实 API 验证登录、退出及未授权访问，提供本任务启动说明。

## 02 — 部门、账号与角色兼任管理

**交付行为：** 管理员在页面维护部门和账号，分别授予管理、研判、上报、处置及特殊上报权限。

**前置依赖：** 01 登录后查看权限内事件列表。

- [ ] 中心管理与研判、部门上报与处置分别授权且可兼任。
- [ ] 特殊账号必须属于部门；管理员未兼任不能执行研判。
- [ ] 初始化参与单位和代表性账号，验证账号停用与越权请求。

## 03 — 数据来源与标准分类维护

**交付行为：** 中心维护来源及事件类别、纠纷类型字典，业务人员能够查询可用项。

**前置依赖：** 02 部门、账号与角色兼任管理。

- [ ] 可维护来源名称、类型、状态及标准分类，受角色权限控制。
- [ ] 停用项不再供新录入选择，历史记录仍能解释。
- [ ] 通过管理页面、查询 API 与数据库持久化结果验证配置生效。

## 04 — 单条事件录入、草稿与原始追溯

**交付行为：** 部门保存草稿、提交事件、查看校验结果与原始记录，中心可代部门录入。

**前置依赖：** 03 数据来源与标准分类维护。

- [ ] 表单使用标准字典，校验必填、日期和已填写身份证；只清洗格式。
- [ ] 账号决定部门和特殊来源，中心代录记录实际操作者；每条仅一名主要当事人。
- [ ] 草稿可自行改删，提交后保留原文与标准化结果，进入待处理状态而非直接计数。

## 05 — 自动人员匹配与档案详情

**交付行为：** 合格事件自动匹配或建立人员档案，中心查看关联事件及身份差异。

**前置依赖：** 04 单条事件录入、草稿与原始追溯。

- [ ] 身份证号与姓名一致才自动匹配；新身份无冲突自动建档，手机号差异不覆盖档案。
- [ ] 无身份证号时仅姓名加有效手机号唯一无冲突可自动匹配；异常进入身份待审。
- [ ] 详情区分身份已确认与尚待重复检测的事件；此时不提前计入有效次数。

## 06 — 身份审核与受控人工建档

**交付行为：** 中心从身份审核池确认归属、补齐身份或按可靠依据人工建档。

**前置依赖：** 05 自动人员匹配与档案详情。

- [ ] 支持候选筛选、关联已有档案及符合条件人工建档，记录理由。
- [ ] 身份证加姓名或姓名加有效手机号是最低依据；身份不足或冲突未解决不建档。
- [ ] 审核结果持久化并推进后续处理，防止并发审核重复生效。

## 07 — 重复候选识别与筛查配置

**交付行为：** 身份确认后按同人、时间与描述相似度显示疑似重复候选。

**前置依赖：** 05 自动人员匹配与档案详情。

- [ ] 默认三天时间范围及相似度阈值可配置；候选展示时间差、相似依据。
- [ ] 身份未明确时不得业务合并，疑似重复不进入有效计数。
- [ ] 使用相似、不同及窗口边界案例验证筛查结果，不将同类自动认定重复。

## 08 — 重复审核与多来源事件归集

**交付行为：** 中心将候选确认为独立事件或合并为一个有效事件，同时保留各部门上报记录。

**前置依赖：** 07 重复候选识别与筛查配置。

- [ ] 先身份后重复；支持确认独立及确认重复，保留审核历史。
- [ ] 合并后有效事件只计一次，原始上报及特殊来源证据不丢失。
- [ ] 各部门仍只查看自己的来源内容，不获得其他部门原文权限。

## 09 — 累计次数风险与计算依据

**交付行为：** 中心在人员档案查看有效次数、最近事件时间、基础等级及计算依据。

**前置依赖：** 06 身份审核与受控人工建档；08 重复审核与多来源事件归集。

- [ ] 0至2条低、3至4条中、至少5条高，覆盖边界。
- [ ] 计数仅包括身份与重复已明确的未删除有效事件；来源上报量另列。
- [ ] 自动处理和人工审核均更新计算结果，提供来源到计算的可见追溯。

## 10 — 特殊来源中风险保底

**交付行为：** 特殊账号有效事件使对应人员至少中风险，并在档案说明可信来源。

**前置依赖：** 09 累计次数风险与计算依据。

- [ ] 特殊账号可上报不同当事人，保底作用于归档人员。
- [ ] 文件或请求内容不能伪造标识；合并及重新归档保留来源证据。
- [ ] 基础高风险不被降为中，保底不可停用或被低等级结果突破。

## 11 — 关键词识别与文本证据

**交付行为：** 系统识别单词及同一事件组合词，在档案和事件展示命中依据及风险影响。

**前置依赖：** 09 累计次数风险与计算依据。

- [ ] 实现初始单词与组合词，可人工标注标签；关键词命中至少中风险。
- [ ] 组合仅同一事件的描述或标签内成立，跨事件不能凑齐。
- [ ] 展示具体事件、来源文本或标签与规则版本，不用不透明分数代替解释。

## 12 — 误命中排除与重新识别

**交付行为：** 中心对字面误命中填写理由后排除，相关文本或规则改变后重新识别。

**前置依赖：** 11 关键词识别与文本证据。

- [ ] 排除必须绑定具体事件、命中、文本和规则依据，记录理由。
- [ ] 排除后风险更新；无关变更不无依据扩大排除失效范围。
- [ ] 相关文本或对应规则变化使排除失效；验证否定语境和恢复识别。

## 13 — 人工风险调整与变化失效

**交付行为：** 中心有理由地调整最终等级，并在风险依据变化后看到调整失效和重新计算结果。

**前置依赖：** 10 特殊来源中风险保底；12 误命中排除与重新识别。

- [ ] 分别展示规则等级、人工调整和最终等级，保存历史原因。
- [ ] 不允许突破特殊来源中风险保底；事件或任务办结本身不降级。
- [ ] 新增有效事件、归档或风险依据改变使调整失效，无关联系方式修改不因此失效。

## 14 — 规则草稿与影响预览

**交付行为：** 中心配置次数、关键词、组合及启停状态，预览预计升降级而不影响当前等级。

**前置依赖：** 13 人工风险调整与变化失效。

- [ ] 草稿可持久化、修改和查看，不立即替换生效规则。
- [ ] 预览展示受影响人数和升降级，考虑特殊保底、排除与人工调整规则。
- [ ] 特殊来源保底不可关闭；预览记录所用规则及数据依据。

## 15 — 规则发布与后台版本重算

**交付行为：** 中心发布规则并查看后台重算进度、完成结果和历史规则解释。

**前置依赖：** 14 规则草稿与影响预览。

- [ ] 发布后所有受影响档案按新版本计算，更新依据和人工调整有效性。
- [ ] 展示进度与失败结果，支持安全重试；旧任务不能覆盖新数据结果。
- [ ] 保留规则及计算历史，并向后续预警功能提供统一的结果变化通知。

## 16 — 统一 CSV 批量导入与失败重导

**交付行为：** 部门用统一 CSV 模板批量导入，查看后台逐行结果、下载失败行并修正重导。

**前置依赖：** 04 单条事件录入、草稿与原始追溯。

- [ ] 合格行继续、错误行失败，提供原始行号和明确原因。
- [ ] 同批完全重复及重试已成功行不新增有效事件；保留原始接收痕迹。
- [ ] 导入经过与表单相同处理入口，身份不足不建档；提供进度与权限内文件下载。

## 17 — 来源映射与分类别名导入

**交付行为：** 中心为不同来源维护字段映射、明确转换及分类别名，部门据此导入不同列名 CSV。

**前置依赖：** 16 统一 CSV 批量导入与失败重导。

- [ ] 映射及版本可保存、选择并反映在接入追溯。
- [ ] 必填列未识别导入前报错，未知分类值使对应行失败。
- [ ] 验证至少两个不同来源模板，文件不能修改可信归属或特殊来源。

## 18 — Excel 导入与格式一致性

**交付行为：** 部门使用 xlsx 获得与 CSV 一致的映射、校验、部分成功和重导体验。

**前置依赖：** 17 来源映射与分类别名导入。

- [ ] 提供对应模板，支持来源映射并复用统一处理入口。
- [ ] 相同输入的 CSV 和 xlsx 得到相同标准化与错误结果。
- [ ] 失败文件、行号、重试与后台进度可用，不扩展到旧xls或宏识别。

## 19 — 凭据化模拟外部批量接入

**交付行为：** 管理员配置来源凭据，调用方批量提交事件并在页面查询接收结果。

**前置依赖：** 04 单条事件录入、草稿与原始追溯。

- [ ] 凭据绑定部门、来源及特殊上报权限，停用后拒绝新调用。
- [ ] 同来源外部编号重复保留接收痕迹不新增有效事件，不跨来源误判相同编号。
- [ ] 逐条返回结果，经统一接入入口后续处理，提供可运行调用与重试示例。

## 20 — 已归档事件修正与删除审核

**交付行为：** 部门申请修正或删除已归档记录，中心审核后生效并更新受影响档案风险。

**前置依赖：** 13 人工风险调整与变化失效。

- [ ] 待审使用旧有效版本，通过后保存前后变化，驳回不改变有效数据。
- [ ] 修改涉及身份、重复或风险时重新走必要流程，删除通过后正确减少计数。
- [ ] 跨部门来源合并记录适用同一审核机制，防止并发审批覆盖新版本。

## 21 — 档案修正、合并与拆分

**交付行为：** 中心修正基本信息、合并重复档案或把错误归集事件拆回正确人员。

**前置依赖：** 20 已归档事件修正与删除审核。

- [ ] 保留变更理由及旧新关系，迁入迁出人员均重算。
- [ ] 归档仍须可靠身份依据，特殊来源随有效事件关联保留。
- [ ] 提供可查询归档变更记录，供后续任务确认功能使用，不硬改历史事实。

## 22 — 风险预警生成、研判与关闭

**交付行为：** 中心筛选预警、查看新增依据，研判后记录结论并明确关闭。

**前置依赖：** 13 人工风险调整与变化失效。

- [ ] 首次中高风险、等级上升触发；开放预警更新依据和新增标记而非刷屏。
- [ ] 关闭必填结论，可暂不派发；关闭不改变风险等级，新有效事件或升级可再次触发。
- [ ] 按等级、姓名、关键词、来源、部门及时间查询，权限与档案一致；数据和规则重算使用同一变化入口。

## 23 — 未研判积压提醒

**交付行为：** 中心查看默认七天未研判的预警，配置提醒阈值并区分已完成研判事项。

**前置依赖：** 22 风险预警生成、研判与关闭。

- [ ] 默认七天可配置，按预警生成及研判记录计算。
- [ ] 重试扫描不重复制造同一提醒，关闭或已研判状态正确排除。
- [ ] 使用可控制的测试时间验证边界，不通过真实长时间等待验收。

## 24 — 单部门任务派发与最小信息授权

**交付行为：** 中心从预警选择有效事件、承办部门及期限，部门看到被明确授权的任务内容。

**前置依赖：** 22 风险预警生成、研判与关闭。

- [ ] 任务必须关联一个人员和至少一条有效事件，一个承办部门。
- [ ] 只提供中心选择的说明、必要联系方式、摘要或附件，保存派发快照。
- [ ] 部门不能由任务访问完整跨部门档案或未授权附件；同人允许多个任务。

## 25 — 部门跟进与处理结果提交

**交付行为：** 承办部门记录任务进展、附件及结果，提交后进入中心待审。

**前置依赖：** 24 单部门任务派发与最小信息授权。

- [ ] 仅具本部门处置权限的账号可跟进或提交。
- [ ] 保存跟进及提交历史，不把提交等同于中心通过或事件办结。
- [ ] 任务页面展示处理阶段和中心待审起点。

## 26 — 中心审核、退回与明确事件办结

**交付行为：** 中心审核部门结果、退回补充或关闭任务，并明确选择需要办结的关联事件。

**前置依赖：** 25 部门跟进与处理结果提交。

- [ ] 退回后可补充再提交，每轮结果与审核保留。
- [ ] 不能默认办结该人员全部事件；任务与事件状态分别维护。
- [ ] 任务和事件办结不降低累计风险，预警仍须另行填写结论关闭。

## 27 — 任务超期与审核等待提示

**交付行为：** 中心和部门区分部门逾期、中心待审核时长，避免责任阶段混算。

**前置依赖：** 26 中心审核、退回与明确事件办结。

- [ ] 按任务期限提醒，处置超期与风险等级预警分开显示。
- [ ] 提交后不继续计部门逾期，中心待审另计；退回补充后的计时规则需在任务实现中明示。
- [ ] 时间边界与重复扫描可验证，不重复生成相同超期事项。

## 28 — 归档变化后的任务确认与历史保护

**交付行为：** 档案合并或拆分影响任务时，未完成任务暂停办结，中心确认后恢复，已关闭任务保留历史。

**前置依赖：** 21 档案修正、合并与拆分；26 中心审核、退回与明确事件办结。

- [ ] 受影响的未完成任务明确标记归档变化，阻止直接提交办结。
- [ ] 中心确认人员、事件、承办部门及授权信息后恢复。
- [ ] 已关闭任务不改写快照，旧新档案重算与来源权限保持正确。

## 29 — 业务首页、统计与关键词下钻

**交付行为：** 业务首页汇总风险、类型、来源部门、热点词、待审核、待处置和超期事项，并提供明细跳转。

**前置依赖：** 23 未研判积压提醒；27 任务超期与审核等待提示。

- [ ] 明确原始上报数、有效事件数和关键词统计单位，不混淆口径。
- [ ] 同一数据修正或归档变化后明细与汇总一致。
- [ ] 普通部门仅看权限内工作概况；中心可看全局，关键词可下钻事件及人员。

## 30 — 权限内风险、事件与统计导出

**交付行为：** 用户导出当前授权及筛选范围内的风险、关联事件或统计结果。

**前置依赖：** 29 业务首页、统计与关键词下钻。

- [ ] 导出条件与列表一致，部门无法通过参数导出其他部门或完整跨部门档案。
- [ ] 明确导出字段与统计口径，结果可追溯筛选条件。
- [ ] 提供成功、无结果和越权场景的行为验证。

## 31 — 跨业务操作历史查询

**交付行为：** 有权限人员按对象、人员和时间查询已有审核、规则、调整、修正及处置操作历史。

**前置依赖：** 15 规则发布与后台版本重算；21 档案修正、合并与拆分；26 中心审核、退回与明确事件办结。

- [ ] 展示关键操作者、时间、原因、前后变化及结果，按对象串联追溯。
