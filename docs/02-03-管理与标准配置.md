# 部门账号管理与来源分类配置

## 进入页面

沿用 [本机启动说明](01-登录与事件列表.md)，登录 [工作台](http://127.0.0.1:5173/)。用 `admin` 进入“部门与账号”或“来源与分类”；初始化示例密码为 `Demo-Only-2026!`，实际以 `DEMO_PASSWORD` 为准。普通业务账号也可打开“来源与分类”，只读查看当前可用项。

本次测试使用独立数据库 `governance_verify`；当前预览改用干净的 `governance_demo`，避免测试账号/分类混入演示。两者位于本任务专用 MySQL 8.0.46 实例 `127.0.0.1:13306`，不改变系统 MySQL 服务。新环境仍按启动说明自行建立空库并配置 `DB_URL/DB_USER/DB_PASSWORD`，不要依赖测试库名。

## 部门与账号

- 部门可新增、改名、启用或停用；类型分综治中心 `CENTER` 与业务部门 `DEPARTMENT`。停用后保留部门、账号和原事件，不删除历史。
- 账号可新增、修改显示姓名/部门/角色/启用状态及重置密码；登录账号建立后固定。编辑时密码留空保持原密码，填入新密码则重置。
- 登录账号使用 3—50 位字母、数字、下划线、点或短横线；密码至少 12 字符，UTF-8 编码不超过 72 字节。接口不返回密码或摘要，密码摘要使用 BCrypt。
- 部门类型、角色归属与特殊上报约束在服务端校验。特殊上报是部门上报的附加权限，必须选择业务部门及部门上报角色。

| 角色编码 | 可见与可操作范围 |
|---|---|
| CENTER_ADMIN | 维护部门、账号、来源和分类；本身不授予事件读取/研判 |
| CENTER_ANALYST | 全局事件读取；来源分类只读；后续承接研判流程 |
| DEPARTMENT_REPORTER | 本部门来源事件读取；后续承接录入/导入 |
| DEPARTMENT_HANDLER | 不读取来源事件，仅在后续任务功能中查看中心授权的任务信息 |
| SPECIAL_REPORTER | 上报附加权限，必须与 DEPARTMENT_REPORTER 兼任并归属业务部门；本轮不生成事件或风险信号 |

中心管理/研判可兼任，部门上报/处置可兼任。管理员可为账号选择多个角色，但不能把中心角色授予业务部门账号，或把部门角色授予中心账号。

账号任何维护操作后撤销原会话，包括角色变更、调部门、密码重置和停用；重新登录后按新权限工作。部门停用及重新启用都会撤销该部门旧会话。修改自己的账号可能需要重新登录，页面会回到登录页。

保存使用版本号，过期版本返回 409；请关闭编辑框、重新进入页面后取最新数据再编辑。所有管理写入串行锁定同一配置锁，且在事务内检查至少保留一名启用中心的启用管理员，防止并发操作锁死管理入口。

## 来源与分类

来源可维护名称、来源类型、启用状态，并在建立时选择全局可用或限定一个部门。类型为 `DEPARTMENT`（部门上报）、`PETITION`（信访）、`EXTERNAL`（外部系统）、`OTHER`（其他）。来源部门归属建立后固定；变更归属需停用并新建，避免重新开放旧来源范围。来源类型只是接入分类，不能伪造特殊上报权限。

字典分 `EVENT_CATEGORY`（事件类别）和 `DISPUTE_TYPE`（纠纷类型）；每项维护编码、名称与状态。编码在同一字典类别下唯一，同类名称也唯一；编码仅用字母、数字、下划线、点或短横线。字典类别/编码建立后固定，可改显示名称、启用或停用。

停用项从可选 API 和业务只读页面中隐藏；停用部门的来源同样不可选。原配置保留，历史查询仍能读取其名称和停用状态。原事件保存的 `event_source/event_category/dispute_type` 文本不被配置改名或停用覆盖；后续录入任务使用稳定引用及接收时快照。本轮不提供事件录入，不能将可选项接口当作已经完成录入校验；任务 04 提交时仍需再次检查最新状态。

中心管理员查看完整配置；中心研判只读全局启用项；部门账号只能查看全局或本部门启用来源。部门访问其他部门的历史来源返回 404，不能通过猜测编号获知其他来源配置。

初始来源“部门上报”；事件类别“民生诉求”“矛盾纠纷”；纠纷类型“救助咨询”“邻里纠纷”“养老服务”，与现有虚构事件一致。字典与来源是演示配置，不声称代表真实地区的完整分类体系。

## 公开接口

所有接口均要求登录；所有 POST/PUT 需按 [既有 CSRF 契约](01-登录与事件列表.md) 带令牌。`/api/admin/*` 额外要求当前有效的中心管理权限。

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/api/admin/roles` | 五种角色编码/名称 |
| GET/POST | `/api/admin/departments` | 完整部门列表/新增 |
| PUT | `/api/admin/departments/{id}` | 修改部门，带 version |
| GET/POST | `/api/admin/users` | 完整账号列表/新增，不含密码摘要 |
| PUT | `/api/admin/users/{id}` | 修改账号/角色/密码/状态，带 version |
| GET/POST | `/api/admin/sources` | 含停用项的来源列表/新增 |
| PUT | `/api/admin/sources/{id}` | 修改来源，带 version |
| GET/POST | `/api/admin/dictionaries` | 含停用项的标准分类列表/新增 |
| PUT | `/api/admin/dictionaries/{id}` | 修改分类，带 version |
| GET | `/api/options/sources` | 当前权限及部门范围内的启用来源 |
| GET | `/api/options/dictionaries?kind=EVENT_CATEGORY` | 指定类别的启用项；另一类别为 DISPUTE_TYPE |
| GET | `/api/catalog/sources/{id}` | 权限范围内历史来源，包括已停用项 |
| GET | `/api/catalog/dictionaries/{id}` | 历史字典项，包括已停用项 |

新增成功 201；更新成功 200。未登录/旧会话 401，角色越权 403，目标不存在/来源范围外 404，无效输入 400，重复名称/编码、旧版本或最后管理员保护 409。没有物理删除端点。

创建账号 JSON 示例：

```json
{"username":"example_staff","displayName":"演示人员","departmentId":2,"roles":["DEPARTMENT_REPORTER","DEPARTMENT_HANDLER","SPECIAL_REPORTER"],"enabled":true,"password":"Example-Password-2026!"}
```

编辑账号应保留 id 对应的版本号，发送 `displayName/departmentId/roles/enabled/version`；用户名可省略或保持原值，密码可省略或空字符串。部门字段为 `name/departmentType/enabled/version`；来源为 `name/sourceType/departmentId/enabled/version`；字典为 `code/name/kind/enabled/version`，新建无需 version。

## 审计与验证

管理写入与审计处于同一数据库事务，失败回滚不会保留半套账号/角色。`tb_operation_log` 存操作者、对象类型/ID、CREATE/UPDATE、成功结果及前后 JSON；用户快照包含 `account` 和不含敏感内容的 `passwordReset` 标记。日志不存密码、摘要或会话令牌。统一历史查询界面仍属于任务 31。
