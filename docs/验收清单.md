## 2. 核心场景

### A. 角色与来源

- [ ] A01 中心管理员无研判角色时，不能调整风险或处理业务审核；兼任后按权限可执行。
- [ ] A02 部门上报权限和处置权限分别生效，兼任可操作两类业务。
- [ ] A03 部门不能通过改详情 ID、接口参数、导出请求或文件地址查看其他部门原始数据与完整档案。
- [ ] A04 特殊账号归属部门，所报事件当事人可以不同于账号持有人。
- [ ] A05 文件伪造部门或特殊来源字段不能获得相应归属与保底标识；接口凭据同样受约束。
- [ ] A06 中心代导入正确记录归属部门与实际操作者。

### B. 接入与清洗

- [ ] B01 两个来源使用不同列名，经映射得到相同标准字段；CSV 和 xlsx 均可操作。
- [ ] B02 正常空格、全半角和明确日期格式被修正，原文不被覆盖。
- [ ] B03 缺少必填列时导入前提示；未知分类、无效日期、无效身份证等给出明确行错误。
- [ ] B04 混合有效与失败行：有效行继续，失败文件包含原始行号和原因；成功不代表已计入风险。
- [ ] B05 修正失败行后重导；再次提交成功行不产生重复有效事件。
- [ ] B06 API 凭据校验、逐条结果、外部编号幂等及接入记录可演示。
- [ ] B07 校验合格但缺少身份的事件能留存与查询，不能直接建档计数。

### C. 匹配、去重与归档

- [ ] C01 身份证号、姓名命中时自动关联；手机号差异仅提示，不覆盖档案。
- [ ] C02 身份证号命中但姓名冲突转人工，不自动归档。
- [ ] C03 身份证号与姓名齐全且无冲突的新人员自动建档。
- [ ] C04 姓名＋手机号唯一且无冲突时匹配；新人员经人工确认与填写理由后建档。
- [ ] C05 只有姓名，或关键身份冲突未解决，持续待审、不建档、不计数。
- [ ] C06 同一来源外部编号重复、同批完全重复不多计；相同编号出现在不同来源不被错误当作确定重复。
- [ ] C07 时间相差 3 天以内且描述相似进入候选，超出配置范围不因同人同类就直接认定重复。
- [ ] C08 身份与重复问题同时存在时先确认身份；重复未明确前不计数。
- [ ] C09 跨部门确认合并后，有效次数为 1，各来源仍存在，各部门仍只看自己的内容。
- [ ] C10 确认非重复后，两次真实事件分别计数。
- [ ] C11 描述中提及第二个人，不自动为第二个人归档或计风险。

### D. 风险及规则

- [ ] D01 事件数 0、2、3、4、5 的边界分别得到低、低、中、中、高。
- [ ] D02 一条特殊账号有效事件至少中风险；合并到普通来源事件后保底证据仍存在。
- [ ] D03 单关键词命中中风险；基础已高时不被保底规则降为中。
- [ ] D04 同一事件“婚＋欠”触发组合；两条不同事件各出现一词不触发。
- [ ] D05 命中能定位到事件、来源、文本片段或人工标签及对应规则版本。
- [ ] D06 否定语境仍按字面命中；中心有原因排除后重算，不能解除特殊来源保底。
- [ ] D07 文本或对应规则变化使相关排除失效；无关文本或规则不能造成无依据的扩大失效。
- [ ] D08 人工调整必填原因；特殊来源档案不能调至低风险。
- [ ] D09 新有效事件、归档变化或规则变更使相关人工调整失效；无关联系方式更新不因此失效。
- [ ] D10 事件或任务办结不减少次数、不自动降级；有效事件删除审核通过后应正确减少计数。
- [ ] D11 规则草稿不影响当前结果；预览显示影响，发布重算所有受影响档案并留存旧版解释。
- [ ] D12 后台重算期间显示进度或计算状态；重复执行或旧任务延迟完成不覆盖新版本结果。

### E. 预警与处置

- [ ] E01 首次进入中高风险或等级上升触发；开放风险预警收到新增依据时更新并标记，不重复刷屏。
- [ ] E02 预警默认 7 天未研判提醒，可配置；派发后按任务期限计部门超期。
- [ ] E03 提交结果进入中心待审，不继续归责为部门逾期，展示中心等待时长。
- [ ] E04 无人员、无有效关联事件或无承办部门不能正式派发任务。
- [ ] E05 部门只能查看任务授权摘要、必要联系方式及选定附件；不能藉由任务进入完整跨部门档案。
- [ ] E06 部门跟进、提交、中心退回补充、再提交、审核通过和关闭形成完整记录。
- [ ] E07 任务关闭不自动办结全部事件；中心只办结明确选择的关联事件。
- [ ] E08 中心填写结论关闭预警，可研判暂不派发；关闭不改变风险等级。
- [ ] E09 已关闭预警后新增有效事件或等级上升可再次触发。
- [ ] E10 档案合并拆分重算旧新人员；未完成任务暂停办结，中心确认后恢复；已关闭任务快照不被改写。

### F. 修正、统计与追溯

- [ ] F01 部门归档后修正或删除先提交申请，待审期间旧版本继续有效，通过后才重算。
- [ ] F02 并发审核同一版本不会重复生效或产生相反结论。
- [ ] F03 风险列表可追溯到计算、事件、全部相关来源及原始接入；关键操作记录原因与前后值。
- [ ] F04 统计区分原始上报数与有效事件数；重复上报不抬高风险次数，来源工作量仍可统计。
- [ ] F05 导出遵守筛选与权限，文件和附件不可通过猜测 ID 越权访问。

## 3. 规模验证

- [ ] 使用可重复生成的虚构数据覆盖约 10 万事件、1 万档案，注明原始上报数与有效事件数。
- [ ] 单次 1 万行导入显示后台进度和逐行结果，覆盖混合错误、重复与重试场景。
- [ ] 约 20 个同时使用会话覆盖列表、详情、录入、审核和任务处理，记录测试环境、请求组合与实测结果。
- [ ] 在批量规则重算并发发生新录入或审核时，最终计数、规则版本与风险结果一致。
- [ ] 展示分页、筛选、后台失败结果和恢复方式，不将未实测的响应时间写为性能承诺。
