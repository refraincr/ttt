# UI 09：来源修正与档案归档审核

本次沿用已确认的墨绿主色、浅灰背景与白色卡片，完成「修正与归档审核」模块的展示与布局调整。对应任务：[09 来源修正与档案归档审核](../.scratch/ui-refresh/issues/09-archive-change-review.md)。

## 页面与交互

- 页面增加核对来源、申请变更、审核留痕的流程提示，以及当前账号的操作范围。
- 来源修正将读取入口、当前记录与版本、修正内容、必填理由及提交操作分组；删除申请显示获批后的影响，未加载时提供明确空状态。
- 申请列表增加待审核数量、中文状态与类型，保留状态代码便于核对；展开后展示申请及审核人员、时间、变更前后对照、完整理由。宽表格及对照区在容器内横向滚动。
- 档案维护提供可用键盘触发的「选择档案」按钮，突出当前档案、版本和核实理由；合并拆分区域明确当前来源、目标与操作依据。
- 历史列表统一类型名称、列宽、空状态，并提供刷新入口。操作期间显示处理反馈并禁用相关输入与重复提交。
- 保留现有来源修正、删除、批准、驳回、档案修正、合并、拆分与历史接口；中心审核与维护入口仍按现有角色显示，部门账号仅跟踪本部门申请。服务端权限、版本冲突及理由校验继续由既有接口执行。

## 验证方式

- `cd frontend; npm run build`：包含 `vue-tsc --noEmit` 及生产构建。构建保留项目既有的大体积 bundle 提示。
- `npx playwright test tests/archive.spec.ts tests/archive-ui.spec.ts --workers=1`：现有真实接口及浏览器业务测试，加上三种尺寸、长文本、键盘操作、权限、加载、错误重试、空状态检查。
- `npx playwright test --workers=1`：全量前端 API 与浏览器回归，最终结果见下方验收结果。
- 浏览器使用本机 Chrome，设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE=C:\Program Files\Google\Chrome\Application\chrome.exe`；使用现有本地前后端与 MySQL 服务。
- 布局测试对 archive 接口使用确定性的虚构长文本数据，登录使用真实账号；`archive.spec.ts` 对真实 API 验证修正、删除、审核、合并拆分、风险重算、历史与权限。截图属于布局证据，不能替代真实业务测试。
