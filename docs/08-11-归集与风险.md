# 08–11 归集与可解释风险

入口：中心研判账号登录 [工作台](http://127.0.0.1:5173/)，进入“归集与风险”。启动及演示密码沿用 [启动说明](01-登录与事件列表.md)。管理员单独角色、部门上报和处置角色无全局风险及审核权限。

## 操作与业务口径

- 身份明确且无重复候选时自动建立独立有效事件，不增加全量内容审批。疑似重复留在“重复审核池”；中心输入来源编号核查，选择“确认独立有效”或“确认重复并归集”，填写理由。合并目标必须身份明确、属于同一人员；目标尚未归集时在同一事务内建立有效事件。
- 来源记录各自保留部门、原文、标准化描述、特殊标识及标签，通过链接归入同一有效事件。审核历史记录结论、有效事件、理由、操作者和时间。已明确记录不接受重复审核；归档后再修正或拆分属于后续20/21号任务。
- 后续相似来源待审不会撤销旧事件已明确的结论。新记录只有审核完成才加入计数；调整筛查配置不会改写已归集结论。重复审核使用版本和统一事务锁，并发同版本审核只生效一次。
- “人员风险档案”按姓名/证件/手机号筛选，展示有效次数、来源上报数、最近有效事件时间、基础等级、最终等级及证据。计数按独立业务事件去重；删除来源、身份未确认、重复未明确的记录不作为有效证据。办结状态不影响计数。
- 基础等级：0–2件低、3–4件中、5件及以上高。同一有效事件以最早来源发生时间作为事件时间；最近有效时间取各有效事件时间最大值，归集晚报记录不虚增事件日期。这是本轮明确记录的实现选择，后续修正可按20号扩展。
- 有效事件中任一来源的账号派生特殊标识使人员至少中风险，基础高风险保持高。待审特殊记录暂不触发保底；普通请求中伪造 specialReport/special_report 不生效。保底没有停用或降级接口。
- 初始字面关键词为“扬言”“杀人”“跳楼”，组合为“婚＋欠”“婚＋钱”。同一有效事件的描述、人工标签及多个归集来源可共同满足组合；不同事件不能凑词。命中至少中风险，不覆盖高风险。
- 在“来源记录核查”中输入标签及理由可重新标注，包括清空标签；中心操作与版本校验受控，审计保留理由和前后快照，原始接收内容不变。风险随自动身份匹配、人工身份审核、重复审核及标签标注同事务重算。
- 人员证据显示具体有效事件、来源记录、描述/标签全文、高亮词语、规则ID与版本。来源详情只展示该条来源文本命中；待归集命中 eventId=null，仅预览，不影响人员风险。合并记录使用真实有效事件编号。部门仍只能读取本部门来源，不返回跨部门来源正文或人员风险。

当前基线规则版本 INITIAL-1，五条关键词规则各为版本1，存于数据库。此阶段只提供规则查询；规则维护、启停与发布重算由14/15号任务接续，误命中排除由12号接续，不引入临时直接改线上规则的入口。

## API

以下均以前缀 `/api/intake`，须登录并具备 CENTER_ANALYST；写请求沿用 CSRF 契约。

| 方法 | 路径 | 数据与用途 |
|---|---|---|
| GET | /duplicate-reviews | 身份明确且尚未归集的记录，最多100条 |
| POST | /records/{id}/duplicate-review | version、decision(INDEPENDENT或MERGE)、targetRecordId、reason |
| GET | /people/{id}/risk | 持久化风险及有效事件/来源/命中证据 |
| PUT | /records/{id}/tags | version、tags（最多500字符）、reason |
| GET | /keyword-rules | 初始关键词、启用状态、版本 |

沿用的 `/records/{id}` 增加 effectiveEventId、keywordHits；仅中心返回有效次数与重复处理历史。`/people/{id}` 的 effectiveCount 改为真实计数。无效身份/跨人目标/缺理由400，越权403，不可见404，过期版本或已审核409；成功200。

## 持久化与升级

新增V8有效事件、来源链接和重复结论，V9风险快照，V10初始关键词；保留V1–V7不变。启动时事务内处理旧的身份已确认记录，并重算档案风险；已有来源链接及人工审核结论保持不变。原系统未确认的虚构演示记录不会擅自归入人员。

所有处理仍通过 IntakeService 统一接入事务，DuplicateScreening、EventConsolidation、RiskCalculation 分别负责候选、归集和解释性风险。当前使用同步计算及串行写锁保证一致性；规模及发布重算属于后续专项验收，不声明已有吞吐量承诺。
