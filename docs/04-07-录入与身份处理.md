# 04–07 事件录入、身份审核与重复筛查

入口：登录工作台，部门上报或中心研判账号进入“录入与身份处理”。沿用 [启动说明](01-登录与事件列表.md)；默认演示密码以 DEMO_PASSWORD 为准。管理员单独角色及仅处置角色无此业务权限。

## 操作

- “事件录入与草稿”：使用启用的来源、事件类别及纠纷类型。草稿允许不完整，归创建者本人，可修改、删除；中心研判代录必须选择启用业务部门。提交时再次校验来源归属及字典状态。
- 发生时间采用 `2026-10-18T09:00:00` 或空格分隔的本地日期时间。清洗使用 Unicode NFKC、首尾空格清除及身份证末位转大写；不改写描述含义。身份证校验格式、出生日期及校验位，手机号仅格式有效时用于匹配。没有身份资料仍可提交至待审池。
- 提交保存原始输入、标准引用及文本快照、实际操作者、账号派生的特殊上报标识；同一草稿重复提交返回同一记录。已提交草稿不可再修改或删除。现有事件列表展示来源记录，非有效事件次数。
- “原始记录与重复候选”：输入提交返回的记录编号。部门只能看本部门记录；中心研判可看全局。原文与标准化后的记录分别显示，历史样例没有原始快照时明确提示。
- 身份证与姓名一致自动关联；新身份证姓名齐全且无身份证或有效手机号冲突才自动建档。无身份证只有姓名加有效手机号唯一无冲突时自动关联。档案手机号不被来源差异覆盖；档案详情逐条展示来源手机号。
- “身份审核”：中心补齐身份、关联档案或人工建档，必须填写可靠依据和理由；最低依据为有效身份证加姓名或姓名加有效手机号。未解决冲突拒绝新建，审核原文保持不变，审计记录修正前后、理由及操作者。版本控制及事务锁保证并发审核仅生效一次。
- “重复筛查配置”：中心研判维护时间窗口（0–365天）及相似度（大于0且不超过1），默认3天和0.7。相似度采用去标点空白后的字符二元组 Dice 系数；不使用事件类别推断重复。窗口包含恰好三天边界。保存配置后重新筛查已有确认身份记录；候选查询按当前配置展示时间差秒数、描述和相似度依据。

身份状态 PENDING/CONFIRMED 独立于重复状态 PENDING/SCREENED/SUSPECTED。SCREENED 表示本次筛查无候选，SUSPECTED 表示存在候选；两者都未完成任务08的重复审核与业务归集。本阶段有效次数均为0，不提前计算风险。

## API

所有接口登录及沿用 CSRF 契约；前缀 `/api/intake`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET/POST | /drafts | 本人未提交草稿/创建（Entry） |
| GET/PUT/DELETE | /drafts/{id} | 读取/修改（payload、version）/删除（?version=） |
| POST | /drafts/{id}/submit | 提交，传 version |
| GET | /records/{id} | 权限内标准化记录、original_payload 及来源追溯 |
| GET | /departments | 中心可代录的启用业务部门 |
| GET | /people?q= | 中心筛选档案（最多100条） |
| GET | /people/{id} | 中心档案详情、关联事件及身份/重复状态 |
| GET | /identity-reviews | 中心待审列表（最多100条） |
| POST | /identity-reviews/{id} | 中心身份审核 |
| GET | /records/{id}/duplicates | 中心查询重复候选 |
| GET/PUT | /duplicate-settings | 中心查询/维护筛查配置 |

Entry 字段：personName、idCard、phone、eventTime、description、sourceId、categoryId、disputeId、departmentId。部门账号 departmentId 可省略或等于自身；中心必填。Review 字段：version、personId（留空新建）、personName、idCard、phone、reason。配置字段：windowDays、threshold、version。删除成功204，其他成功200；不合格400、未登录401、越权403、不可见404、版本冲突409。
