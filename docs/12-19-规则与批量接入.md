# 12–19 规则治理与批量接入

入口：登录后选择“规则与批量接入”。中心研判员可排除误命中、调整风险、维护规则和来源映射；部门可导入及查看自己的批次；管理员可创建和停用外部凭据。仅管理员账号不会因此获得来源事件读取权限。

## 规则治理

- **12**：输入人员编号查看具体事件、规则及原文证据，填写理由后排除。排除绑定具体命中指纹，相关文本或对应规则改变后永久失效；恢复旧文本也不会恢复排除。无关规则的编辑不改变原规则版本。
- **13**：分别展示规则等级、有效人工等级与最终等级。调整必须填写理由并提交当前依据指纹；特殊来源不得调至低风险。依据变化后保存失效状态，历史理由和操作者保留。事件计数仍按既有有效事件口径，本轮不新增办结降级逻辑。
- **14**：新建、保存或修改草稿，配置次数阈值、单词、组合词与启停；草稿不影响当前规则。预览保存完整配置、草稿版本、每个人员的前后计算依据和升降级统计。固定特殊来源保底不提供关闭选项。编辑后需重新保存、预览。
- **15**：发布当前已预览的草稿后，后台每次处理20个人员，页面刷新查看进度。失败可重试，旧规则任务标记SUPERSEDED；全局事务锁保证计算与写入不交错，旧任务不会覆盖新规则结果。重启后未完成任务继续处理。规则发布后读取接口若发现旧缓存版本，会用新版本计算。历史快照和规则版本保留，等级变化写入`tb_risk_notification`，供后续预警消费，本轮不提前实现22号预警。

风险接口前缀 `/api/risk-governance`：

| 接口 | 用途 |
|---|---|
| GET `/people/{id}` | 当前依据、命中指纹、调整及排除历史、计算历史 |
| POST `/exclusions` | personId、eventId、ruleId、fingerprint、reason |
| POST `/adjustments` | personId、level、fingerprint、reason |
| GET、POST `/rules` | 读取发布记录/任务；保存草稿(id、version、rules) |
| POST `/rules/{id}/preview` | 计算并留存预览 |
| POST `/rules/{id}/publish` | 携带version发布 |
| POST `/jobs/{id}/retry` | 失败重试 |

## 文件导入

- **16**：选可信来源，下载统一CSV模板，上传后刷新查看逐行结果。合格行继续、错误行失败，保留原始行号、原始文件和每行输入；失败CSV附带原因，修正后重新上传。成功行和同批完全重复行通过账号、来源和标准化载荷指纹防止重复接收，重试仍留存新批次行。身份信息不足仍进入待审，不擅自建档。
- **17**：中心选择来源，设置字段对应列名、日期转换、事件分类和纠纷别名（每行`原值=标准分类编号`）。同名保存新增版本，旧批次保存完整映射快照。缺列在创建批次前拒绝，未知分类逐行失败。文件列不能控制部门、来源或特殊标记。中心导入需使用绑定部门的来源；部门归属始终来自当前账号。
- **18**：同一入口接收xlsx；下载相同映射的xlsx模板。身份证、日期建议使用文本，统一日期示例`2026-10-18T12:00:00`。只支持单工作表、最多5000行、5MB；拒绝公式、旧xls。CSV和xlsx共用转换、分类校验、接入、失败CSV、去重和后台进度。

接口：GET `/api/batches` 查询权限内批次；POST同路径multipart上传`sourceId`、可选`mappingId`、`file`。GET `/api/batches/{id}`读取结果，`/{id}/original`下载原始文件，`/{id}/failures`下载失败CSV。模板为`/api/batches/template?sourceId=...&format=csv或xlsx&mappingId=...`。映射GET/POST `/api/batches/mappings`。

批次状态按行统计：PENDING、SUCCESS、FAILED、DUPLICATE。任务每秒领取至多20行，每行独立事务；失败不会回滚其他行。下载校验原提交账号或中心研判权限。CSV失败文件对公式前缀做转义。

## 外部接入

**19**：管理员创建绑定部门、来源与特殊权限的凭据，明文仅创建时展示，数据库保存散列。可在页面停用，停用、来源或部门不可用时拒绝新调用。外部编号按来源去重，不跨来源；每次有效或重复接收均保存接收痕迹，失败逐条记录原因。

凭据接口GET/POST `/api/batches/credentials`，DELETE `/api/batches/credentials/{id}`停用。中心通过GET `/api/batches/receipts`或页面查看接收结果。

以下PowerShell示例使用管理员页面创建的token，分类编号从实际配置中选择；重复运行使用相同externalId可验证安全重试：

```powershell
$token = Read-Host '输入外部凭据'
$category = [long](Read-Host '事件分类编号')
$dispute = [long](Read-Host '纠纷类型编号')
$items = @(@{externalId='demo-external-001'; payload=@{
  personName='虚构接入人员'; idCard=''; phone='';
  eventTime='2026-10-18T12:00:00'; description='虚构外部接入演示';
  categoryId=$category; disputeId=$dispute
}})
$body = ConvertTo-Json -InputObject $items -Depth 5
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:5173/api/external/events' `
  -Headers @{Authorization="Bearer $token"} -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

该接口使用Bearer凭据，不依赖会话和CSRF；其他写接口继续校验会话及CSRF。单批1–100条，每条独立事务与结果；归属和特殊标记只来自凭据，不采信载荷伪造。所有渠道最终调用`IntakeService.save/submit`，复用身份、重复筛查、归集及风险计算。
