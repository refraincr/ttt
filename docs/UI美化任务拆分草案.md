# 全项目 UI 美化任务拆分草案

状态：用户已确认整体实施方案及本草案的 12 项拆分，已发布[正式任务索引](../.scratch/ui-refresh/README.md)；01 已完成，后续实施与验收状态见正式任务。

来源：[UI 美化设计](UI美化设计.md)。用户已确认墨绿系精致政务风格、视觉与布局一起优化、电脑办公优先和均衡信息密度，以及下列具体拆分及整体实施方案。

## 共同边界与验收

- 覆盖登录页和现有全部九个业务模块，保留业务规则、角色权限、接口、数据口径与功能入口。
- 每项交付都能通过真实账号和现有接口独立演示对应流程，包含相关表单、列表、弹窗或抽屉及反馈状态的完整体验；无需为 UI 改动新增数据库或接口工作。
- 统一墨绿主色、浅灰背景、白色卡片、字体层次、圆角、边框及克制的阴影，采用均衡办公信息密度。
- 以 1440×900、1280×800 桌面及 390×844 窄屏作为布局检查样本；窄屏导航可访问、操作不被遮挡，宽表格在容器内横向滚动。
- 每项完成时运行类型检查、构建和相关既有行为测试，记录实际结果及代表性截图；必要时补充布局或交互回归检查，不编写只复述 CSS 的测试。
- 各任务同步验证权限、加载、空数据、错误提示，以及长文本和适用的表单校验；不得用静态展示替代现有真实交互。
- 第一项建立可增量采用的公共视觉约定，并先在事件查询链路落地；后续页面逐步迁移，未迁移页面仍可使用。不单设只能交付样式文件的基础任务。

## 01：工作台框架与事件查询样板

**Blocked by:** None (can start immediately)

**What to build:** 登录后的左侧导航、顶部账号区与事件列表采用新风格，用户能在权限内筛选、翻页和查看事件详情，为其他页面提供实际可用的统一样板。

- [ ] 导航选中态、标题、内容宽度、筛选区、主要操作、表格、状态标签、分页及详情抽屉形成一致层次。
- [ ] 现有姓名或描述、关键词、部门、时间筛选及重置、详情、刷新和退出链路正常；无事件权限账号仍显示正确提示。
- [ ] 公共视觉约定可被后续页面逐步采用，其他页面保持可用；按共同要求完成验证。

## 02：登录页与身份反馈

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 登录页延续工作台的视觉规范，账号输入、密码输入、登录反馈及进入工作台的体验完整且清楚。

- [ ] 品牌介绍、登录表单与演示环境说明层次清晰，窄屏可完整操作。
- [ ] 登录成功、空值校验、错误凭据、提交中和退出后重新登录按现有逻辑工作；按共同要求验证。

## 03：部门与账号管理

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 管理员能清晰查找部门和账号，通过统一表单完成现有管理操作并查看结果。

- [ ] 部门与账号标签页、查询、列表、角色展示及编辑弹窗遵循样板规范。
- [ ] 既有新建、编辑、启停、角色兼任与密码相关入口及约束保持有效，非管理员访问限制正确；按共同要求验证。

## 04：来源与分类维护

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 用户能按权限浏览来源和分类，管理员能通过清晰的维护表单完成已有配置操作。

- [ ] 来源、分类及相关字典维护的标签页、工具栏、列表与弹窗风格统一。
- [ ] 普通账号只读、管理员维护及现有引用约束提示保持正确；按共同要求验证。

## 05：事件录入与身份处理

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 上报人员能按清晰的表单分组录入、保存草稿和提交事件，有权限人员能继续完成现有身份处理流程。

- [ ] 当事人信息、事件信息、来源与原始记录相关内容分组清楚，必填项、校验提示及主要操作易识别。
- [ ] 草稿、提交、匹配结果、身份待审、受控建档及本模块重复筛查相关操作按现有权限工作；按共同要求验证。

## 06：归集与风险研判

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 研判人员能检索人员风险档案、阅读风险依据并完成既有重复审核与来源核查。

- [ ] 风险等级、有效事件次数、来源记录数、命中证据和人工调整依据层次清楚，保持数据口径差异。
- [ ] 人员档案、重复审核池、关键词规则和来源记录核查全部可操作，现有人工调整、误命中处理及归集动作保持有效；按共同要求验证。

## 07：规则草稿、预览与发布

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 有权限人员能清楚区分规则草稿、影响预览、发布和重算状态，完成现有规则治理链路。

- [ ] 规则配置表单分组清楚，草稿、当前版本、预览结果、发布及后台重算反馈层次明确。
- [ ] 草稿编辑、保存、影响预览、发布与重算状态查看按现有接口和角色限制工作，批量接入入口仍可用；按共同要求验证。

## 08：批量导入、映射与接入管理

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 用户能清楚完成现有批量文件导入，查看批次结果、定位失败项并重导；有权限人员能维护映射及外部接入配置。

- [ ] 文件选择、来源映射、批次状态、成功与失败结果、失败重导及凭据相关界面组织清晰。
- [ ] CSV、Excel、映射、别名和模拟外部接入相关现有 UI 流程保持有效；不增加新的接入渠道或公开敏感信息。
- [ ] 规则发布页面和角色可见性保持有效；按共同要求验证。

## 09：来源修正与档案归档审核

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 用户能核对来源记录并提交修正或删除申请，有权限人员能对照变更前后内容完成审核及档案关系维护。

- [ ] 来源加载、修正表单、申请记录、前后对照、审核理由及审核动作层次清楚。
- [ ] 既有来源修正、删除申请、批准或驳回、档案修正、合并拆分及历史查看按权限工作，保留核实理由等约束；按共同要求验证。

## 10：预警研判与部门处置

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 中心与部门能在各自权限内识别预警和任务状态，完成研判、派发、跟进、提交及审核等现有操作。

- [ ] 预警与任务列表、详情、处置记录、积压或超期提示及动作区层次一致，风险等级与任务状态清楚区分。
- [ ] 研判、关闭、派发、部门反馈、中心确认或退回、事件办结及归档变化后的确认入口保持有效。
- [ ] 最小信息授权和历史保护保持有效；按共同要求验证。

## 11：业务概况、导出与操作追溯

**Blocked by:** 01 工作台框架与事件查询样板

**What to build:** 用户能阅读权限内真实统计，按关键词下钻，查看人员或事件详情，并完成现有导出和历史查询。

- [ ] 概况指标、部门分布、热点关键词、明细、导出区和操作历史层次清楚；只展示真实接口返回的数据。
- [ ] 当前筛选条件、统计口径、下钻、详情抽屉、权限内导出及历史筛选保持一致有效；按共同要求验证。

## 12：全项目一致性与跨模块验收

**Blocked by:** 02、03、04、05、06、07、08、09、10、11

**What to build:** 用户跨业务模块连续操作时获得一致、完整的界面体验，交付可核查的全项目改版结果。

- [ ] 登录页与九个模块、全部角色可见入口、弹窗和抽屉完成覆盖检查，清理已迁移界面的遗留样式冲突。
- [ ] 在约定桌面和窄屏尺寸复核导航、筛选、表格滚动、表单、长文本及反馈状态，修复遮挡和溢出。
- [ ] 完成全项目类型检查、构建和适用的既有 API/浏览器回归，记录结果、截图及未解决限制；各模块验证在其自身任务内已完成。
