在根目录准备 `.env` 后：

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose logs -f api
```

等待后端启动及初始化完成，访问 [Compose 工作台](http://127.0.0.1:8088/)。仅数据库端口与网页端口绑定本机，API 在 Compose 内网中由 Nginx 代理。数据库存储在 `mysql-data` 命名卷中；`docker compose down` 保留数据。删除卷会删除演示数据库，不应用于持久化验收。

## 预置账号与操作

所有预置账号使用初始化时指定的 `DEMO_PASSWORD`，密码以 BCrypt 摘要保存。只在空账号库且显式提供演示密码时初始化，重启不会覆盖账号或重复生成事件。清空 `DEMO_PASSWORD` 则不生成任何样例。

| 账号 | 身份 | 范围 |
|---|---|---|
| center | 中心研判员 | 三条来源记录及详情 |
| civil | 民政上报员 | 民政局两条 |
| police | 公安处置员，未兼任上报 | 可登录，事件接口返回 403 |
| admin | 中心管理员，未兼任研判 | 可登录，事件接口返回 403 |
| disabled | 停用账号 | 拒绝登录 |

具备事件读取权限的账号登录后可搜索当事人或问题描述，点击查看详情；无该权限的账号显示权限说明。仅处置角色不得读取来源事件，兼任上报角色后才具备本部门记录读取权限。刷新页面保留会话；点击退出登录后返回登录页，旧会话无法继续读取事件。会话空闲 30 分钟到期，后端重启后需重新登录。所有数据均为明确标注的虚构案例。

## API 契约

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/auth/csrf` | 匿名可用，返回 `headerName`、`token` 并建立会话 |
| POST | `/api/auth/login` | 表单编码 `username`、`password`，成功 204，凭据错误/停用 401 |
| GET | `/api/auth/me` | 返回账号展示信息、部门和角色，未登录 401 |
| POST | `/api/auth/logout` | 注销会话，成功 204 |
| GET | `/api/events?page=1&size=10&q=张某` | 返回 `{items, total}`，来源上报数口径，时间/编号倒序 |
| GET | `/api/events/{id}` | 返回权限内来源记录，不存在或跨部门均 404 |

分页限制：`page` 1—1000000，`size` 1—100，搜索最多 100 字符；非法输入返回 400。搜索按字面匹配姓名或问题描述，`%` 不是通配符。客户端不能扩大查询部门范围。

列表/详情字段：`id, personName, eventTime, eventCategory, disputeType, eventDescription, eventSource, departmentName, isCompleted`。其中 `personName` 对应原字段 `party_name`，`eventTime` 对应 `occurred_at`，`eventDescription` 对应 `problem_description`。日期为上海当地时间 ISO 字符串；`personName` 可空。没有开放身份证号、联系方式、路径、档案关联或综合风险字段。

认证使用 HttpOnly/SameSite=Lax 会话 Cookie；所有 POST 都必须先获取 CSRF 并在返回的 headerName 中携带 token。登录成功后令牌轮换，下一次 POST 重新获取；缺失令牌返回 403。机制遵循 [Spring Security CSRF 文档](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。公网 HTTPS 部署可配置 `COOKIE_SECURE=true`。

登录成功、失败及退出记录到 `tb_operation_log`，不记录密码或会话令牌。统一历史查询界面属于任务 31。

## 数据结构与范围

`V1__accounts.sql` 创建最小部门、账号、角色关联；`V2__event_listing.sql` 创建完整 29 字段事件主表，保留用户提供 SQL 的字段类型/默认值、六个原索引和 `utf8mb4_general_ci`。追加 `department_id`、`identity_review_state`、`duplicate_review_state` 及查询索引。其他新表采用设计建议的 `utf8mb4_0900_ai_ci`。`review_status` 保持原 SQL 的默认 0，`version` 默认 1；独立审核状态初始均 `PENDING`，本任务不进行匹配、计数或风险计算。

`V3__authentication_audit.sql` 创建当前登录行为所需的操作日志字段。以后业务操作在对应任务中追加字段与记录。账号/部门管理界面属于任务 02；事件录入属于 04。本任务仅提供读取，不提供无授权写入入口。

Flyway 在启动时自动执行版本化迁移；不要修改已经在真实业务环境执行过的迁移。此次是空库初始化，并未实现带存量数据的旧系统迁移或推断历史部门归属。
