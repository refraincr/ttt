# 27–32 最终功能与交付验收

## 操作入口

「预警与处置」显示部门逾期、中心待审秒数及归档待确认。部门逾期仅在 ASSIGNED/RETURNED 阶段、当前时间大于等于原期限时成立；SUBMITTED 阶段停止部门逾期，单独从本轮 submitted_at 起算中心等待；退回补充不增加期限，仍使用原期限。时钟按 Asia/Shanghai，可控时钟测试覆盖整秒边界和阶段切换。提示为动态计算，不反复插入提醒记录。

档案合并或拆分时，相关未关闭任务在同一事务内标记 archive_pending 并推进版本，阻止跟进提交和关闭审核。中心在任务详情确认新人员、有效事件、承办部门、授权说明/联系方式/摘要并填写理由后恢复到退回补充阶段。旧派发快照不改写，确认前后数据另表保存；已关闭任务保持原历史。确认沿用原承办部门及附件历史；需要转交部门时重新派发，避免旧附件因修改部门而扩权。

「业务概况与追溯」提供当前账号授权内概况、事件分页、风险明细、关键词下钻、CSV 导出和历史查询。筛选为姓名或事件描述；风险查询包含对应来源描述匹配的人员，关键词下钻继承当前筛选。原始上报数是未删除来源记录数；有效事件数是这些来源对应的不同有效事件编号数；关键词按人员/有效事件/词去重，不因多条规则包含同一词重复计数。部门上报角色只看本部门来源，处置角色只看本部门任务；完整风险和全局关键词仅向中心研判开放。

CSV 导出与对应列表使用相同筛选和权限规则，导出包含筛选条件。无结果明确标记；条件及单元格均转义，防止公式前缀执行。统计类型及来源分布按上报数，风险分布按未合并人员数，不混用口径。数据修正后按当前有效关系查询，不维护独立可能过时的汇总副本。

操作历史支持对象类型、业务对象编号、人员编号及含首尾的本地时间范围。归档、事件变更、规则、调整、排除、预警研判、任务跟进及每轮审核保留内容/理由和前后数据。查询通过业务关系关联人员，部门只查询本部门来源申请或授权任务历史。

## 新增接口

- `POST /api/cases/tasks/{id}/confirm`：version、personId、eventIds、departmentId、instruction、contact、summary、reason；过期版本/未确认提交返回 409。
- `GET /api/cases/tasks` 与详情增加 departmentOverdue、reviewWaitSeconds、archive_pending。
- `GET /api/insights/dashboard?q=`：权限内汇总；`events?q=&page=1&size=50`：事件分页（最多 100）；`risks?q=`：中心风险列表。
- `GET /api/insights/keyword?term=&q=`：中心关键词下钻到人员与有效事件及证据。
- `GET /api/insights/export?kind=events|risks|statistics&q=`：CSV。
- `GET /api/insights/history?type=&objectId=&personId=&from=&to=`：历史记录。对象类型包含 TASK、ALERT、ARCHIVE、RECORD_CHANGE、ADJUSTMENT、EXCLUSION、RULE，以及已有审计对象类型。

V15 新增任务待确认标记和确认历史表。批量导入上限由 5000 提升为 10000 行，仍保留单文件 5MB 限制。
