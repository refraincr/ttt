## 2. 角色与可见范围

| 角色或权限 | 职责及边界 |
|---|---|
| 中心系统管理员 | 管理账号、部门、来源和权限；不因管理员身份自动取得业务研判权限。 |
| 中心研判人员 | 查看跨部门数据，管理风险规则，执行身份与重复审核、档案修正、等级调整、预警研判和任务审核。 |

同一账号可兼任角色或权限。普通部门不能直接查看跨部门人员档案、综合风险等级及其他部门原始事件。任务授权只开放中心选定的信息，不扩大完整档案访问权限。导出与附件访问遵守相同的数据范围。

特殊账号持有人不是事件当事人。特殊账号可以上报涉及不同人员的事件，最低中风险约束作用于被归档的事件当事人。

## 3. 数据接入与质量

接入方式为单条表单、CSV、Excel `.xlsx` 和批量提交 API。第一版不要求 `.xls`、含宏文件或图片识别。

提供统一模板，并按数据来源维护字段映射、明确的类型转换和分类别名映射，不自动猜测含义。事件类别、纠纷类型等使用统一字典。无法识别必填列时在导入前提示；具体行的分类值无法映射时，该行失败。

自动清洗限于不改变含义的修正，例如空格、全半角和明确日期格式。发生时间、问题描述或其他必填字段缺失、日期无法解析、已填写但无效的身份证号等导致该行失败。身份字段缺失与身份字段填写错误不同：允许缺少身份信息的合格事件进入审核池，但不能直接建档或计入人员风险。

部分成功策略：合格行继续，失败行给出原始行号、字段及错误原因，并提供可修正重导的失败文件。重复提交已成功数据不新增有效事件。

部门归属及特殊来源由登录账号或接口凭据决定。中心代导入需选择归属部门，记录实际操作人；文件不能自行赋予特殊来源。接口凭据绑定部门、来源及特殊上报权限，调用方提供外部记录编号，逐条返回接收结果，页面可查接入记录。

原始内容、原始行号或外部编号、接入批次、来源、操作身份及处理结果均可追溯。原始文件与错误文件按批次留存，原始记录与标准化事件通过关联追踪。

## 4. 人员匹配与建档

每条事件只有一名主要当事人。其他人员可保留在问题描述中，不建立额外人员关联，不自动计入其他人员风险。

处理顺序：数据校验与标准化 → 身份匹配或审核 → 疑似重复审核 → 有效事件归集 → 风险计算。新事件没有全量内容审批环节，只有异常进入人工审核。

| 情况 | 处理 |
|---|---|
| 有效身份证号命中档案，姓名一致 | 自动关联。手机号差异提示，不直接覆盖档案。 |
| 有效身份证号命中档案，姓名冲突 | 转人工审核，不自动归档。 |
| 有效身份证号与姓名齐全，没有对应档案且无身份冲突 | 自动新建档案。 |
| 没有有效身份证号，姓名＋有效手机号唯一匹配且无身份冲突 | 自动关联已有档案。 |
| 姓名＋有效手机号未匹配档案 | 人工确认建档，填写理由，并排除未解决的身份冲突。 |
| 身份不足或多候选、冲突未解决 | 留在审核池，不建档、不计入人员风险。 |

人工建档的最低身份依据是“有效身份证号＋姓名”或“姓名＋有效手机号”。不能仅凭姓名新建身份待补全档案。

档案支持基本信息修正、合并和事件拆分。人员身份审核与重复审核分别记录，不能用单一“已审核”状态掩盖另一环节未完成。

## 5. 去重与有效事件

确定重复包括同一来源的相同外部记录编号、同一批次完全相同的记录。保留接收痕迹，不重复生成有效事件。

跨来源疑似重复按同一人员、发生时间接近、问题描述相似筛选；默认时间差不超过 3 天，时间与相似度阈值可配置。只作为候选提示，不自动做跨来源业务合并。身份未确认时可显示线索，但先完成身份审核。

疑似重复在审核完成前不参与风险计数。审核可确认合并或确认独立有效。跨部门合并保留各部门上报记录，共同关联一个有效事件；各部门只看自己的内容，修正由中心确认。

有效事件的口径：校验合格、人员归属已确认、重复状态已明确且未被逻辑删除的独立业务事件。一次真实事件无论有多少来源上报，只计一次。事件办结后仍是有效事件。

合并不能丢失来源证据、关键词依据和特殊来源标识；命中需要始终能追溯到具体来源文本。首次身份匹配后若仍待重复审核，不得先计数再扣除。

## 6. 风险规则与解释

风险主体为人员档案，低、中、高三档。待审核不是第四档风险；特殊上报不是部门或事件类别。

初始基线：

| 条件 | 结果 |
|---|---|
| 有效事件累计 0～2 条 | 基础低风险 |
| 有效事件累计 3～4 条 | 基础中风险 |
| 有效事件累计至少 5 条 | 基础高风险 |
| 有效关联事件含特殊账号来源 | 最低中风险，固定约束 |
| 命中已启用的单关键词规则 | 最低中风险 |
| 同一事件命中一组组合关键词 | 最低中风险 |

初始关键词参考 Word：单词“扬言”“杀人”“跳楼”；组合“婚＋欠”“婚＋钱”。关键词和次数阈值可维护，规则可启停；特殊来源保底不可关闭。组合词不跨事件凑齐，同一事件的问题描述与人工标签可共同构成命中依据。

第一版按字面命中，不实现语义识别。中心可以说明理由排除某事件的某条误命中；相关文本或对应规则变化后，排除失效，重新识别。排除关键词不能解除特殊账号保底。

计算顺序为有效事件计数 → 基础等级 → 各风险信号保底 → 当前有效人工调整 → 再次检查不可突破的特殊来源保底。分别保存规则等级、人工等级、最终等级和对应依据。

任务或事件办结不自动降低风险。中心可人工调整等级并填写原因；影响风险的数据或规则变化后，人工调整失效，按新依据重算并提示研判。仅修改联系方式等无关信息不因此使调整失效；若修改导致身份重新归档，则属于影响风险的变更。

规则采用草稿、影响预览、发布与版本留存。发布前展示预计升降级数量，发布后重算受影响档案，同步依据、人工调整有效性及预警。不能只对后续新增数据使用新版本。

## 7. 预警及处置

首次进入中高风险、风险等级上升、处置超期时产生相应提醒。同一档案已有未关闭风险预警时，更新依据并标记新增信息，避免反复新建相同提醒。处置超期单独提示。

中心研判后决定派发任务或暂不派发。预警必须由中心填写结论后明确关闭，不因任务办结或等级变化静默关闭。关闭不改变风险等级；关闭后新增有效事件或等级上升可再次触发。

默认预警生成后 7 天未完成研判提醒，阈值可配置。派发任务后按任务截止时间判断超期。部门已提交结果待中心审核时，不继续算部门逾期，单独展示中心待审核时长。

每项任务必须关联一个人员档案、至少一条有效事件和一个承办部门，明确期限，保留派发时信息快照。同一人员可以有多项任务，不做一项任务的多部门主协办流程。

部门可查看任务说明、必要联系方式及中心选择的摘要或附件，记录跟进、提交结果。中心审核可通过或退回补充，通过后关闭任务；可明确选择将哪些关联事件办结，不默认办结该人员所有事件。

人员合并、拆分影响任务关联时：已关闭任务保留原始历史快照；未完成任务标记归档变化、暂停提交办结，由中心确认人员、事件和部门后继续。相关档案重新计算风险。

## 8. 修改、审计和统计

草稿允许自行修改、删除。已归档有效记录的修正或删除，部门提交申请，中心审核通过才生效；审核前使用旧有效版本。通过后保留前后版本并执行必要的匹配、去重和风险重算。合并来源记录适用同一修正原则。

关键操作记录操作者、时间、对象、前后变化、原因和结果，覆盖规则发布、审核、档案合并拆分、等级调整、关键词排除、修正删除及预警处置。

提供风险数量、类型分布、部门数据量、热点关键词和待审核数量等统计，以及权限内的风险列表、事件和统计导出。人员风险、有效事件数量、原始上报数量、关键词次数必须分别标明口径，不能混用原始记录数与有效事件数。

## 9. 技术、规模和交付

- 前端：Vue 3、TypeScript、Element Plus；实用型业务后台，非独立展示大屏。
- 后端：Spring Boot；数据库 MySQL 8.0，沿用既有字段设计约定。
- 设计验收规模：约 10 万事件、1 万档案、单次导入 1 万行、约 20 人同时使用。导入和批量重算提供后台进度。
- 运行：本机开发启动与 Docker Compose 部署并行提供。
- 交付：前后端源码、初始化及样例数据、字段说明、需求与设计、规则说明、接口说明、安装操作说明、测试记录及演示材料。

上述数量是设计及测试目标，不是已经实现或测得的能力。响应时间和吞吐实测应记录测试硬件、数据分布及请求组合，不凭空宣称性能指标。
