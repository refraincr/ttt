# 20–21 修正审核与档案变更

新增导航「修正与归档审核」。部门上报账号可加载本部门已归档来源编号、申请修正或删除，并查看自己的申请和审核理由。中心研判账号可操作全部来源和档案；单独管理员、处置角色不因此获得研判权限。

## 操作

1. 加载来源记录，选择修正或删除。修正支持姓名、身份证、电话、发生时间和描述；来源、部门和特殊标记不由申请内容指定。填写理由后提交。
2. 中心在申请表展开行，核对变更前与申请变更后，填写审核理由并批准或驳回。待审及驳回均保留原有效数据。
3. 批准修正后重新匹配身份、检测重复并重算旧新档案风险；不满足自动匹配的内容进入已有身份审核池。批准删除只软删除申请的来源，合并事件中其他部门来源仍有效。原始上报及申请前后快照保留。
4. 中心查询并点击档案，填写可靠依据和理由修正基本信息。修改档案不会改写来源原文。联系方式修正不凭空使人工风险调整失效。
5. 合并需选择另一个现有目标档案，姓名一致、身份证无冲突且目标有可靠身份依据；不同电话可在核实为同一人的理由下合并。源档案保留为已合并记录，不再参与自动匹配。源身份证在目标未持有时迁入目标；各来源和有效事件关系保留，不直接把不同有效事件当作同一事件。
6. 拆分按已加载的单条来源归入现有目标档案，理由应写明核实依据。采用目标已核实身份后重新检测重复，可能进入重复审核池；其他来源留在原档案。特殊证据始终随来源保留，迁入迁出双方风险重算。

## API

所有写操作需要登录和 CSRF。版本不符返回 409；审核重复执行返回 409。所有归档写操作与已有录入、审核和规则重算共用事务锁。

- `GET /api/archive/requests`：权限内最近 200 条申请，含原版本、申请内容和前后快照。
- `POST /api/archive/records/{id}/requests`：`version, kind(CORRECT/DELETE), payload, reason`；payload 为 `personName,idCard,phone,eventTime,description`。
- `POST /api/archive/requests/{id}/review`：`approve, reason`。批准时再次验证来源版本；过期申请可驳回后重新申请。
- `GET /api/archive/people?q=`：中心查询未合并档案，含 version。
- `PUT /api/archive/people/{id}`：`version,name,idCard,phone,reason`。
- `POST /api/archive/people/{id}/merge`：`version,targetPersonId,targetVersion,reason`。
- `POST /api/archive/records/{id}/split`：`version` 为来源版本，另传 `targetPersonId,targetVersion,reason`。
- `GET /api/archive/history`：中心查询最近 200 条档案修正、合并、拆分历史；含旧新人员、来源编号、理由、操作者、时间和快照，供后续任务确认使用。

Flyway V13 新增申请和归档历史表，以及人员版本和合并指向字段。历史审核、重复决策和风险历史仍保留。
