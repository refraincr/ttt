# 22–26 风险预警与部门处置

入口：导航「预警与处置」。中心研判角色看到预警、提醒配置、派发与审核；部门处置角色看到本部门任务。单独管理员或上报角色不获得这些权限。既有管理员、上报、研判、处置兼任规则继续生效。

## 预警与积压

- 有效事件处理、身份/重复审核、修正删除、归档变化、人工调整及规则后台重算均通过 RiskCalculation 的统一变化入口处理预警。
- 首次达到中高风险生成预警。同人已有开放预警时更新依据并标记新增信息，保留同一预警编号。研判后清除新增标记，历史保存当时的完整风险快照、结论、操作者和时间。
- 关闭必须填写结论，也可先记录研判并说明暂不派发。关闭不修改风险等级。已有关闭预警后，新有效事件或等级上升可以再次触发，包括新增有效事件后仍为低风险的情况。
- 相同规则重新发布、风险依据完全相同时只刷新版本解释，不误标新增依据；风险依据或最终等级改变则更新开放预警。页面展示本次依据、命中词及文本证据、相对最近研判新增的有效事件，同时区分当前风险。
- 支持等级、姓名、命中关键词、来源、来源部门、生成时间、状态及未研判积压筛选，列表分页。来源和部门条件匹配同一来源证据。
- 默认 7 天未研判提醒，可配置 1–365 天。从预警生成时刻起算，到达阈值即列入；已研判或关闭排除。提醒是按业务时钟实时计算的预警视图，不额外插入提醒记录，因此重复查询不会重复制造事项。开放预警研判后又有新增依据时显示新增标记，已有研判记录不被当作从未研判。

## 派发与处置

1. 中心打开预警，选择该人员至少一条当前有效事件、一个启用承办部门及未来期限，填写任务标题和处置说明。按需要填写联系方式、摘要，并上传和选择明确授权的附件。
2. 系统保存派发时的独立快照。部门只看到任务内这些授权信息及本任务跟进/审核历史，没有完整跨部门人员档案、原始来源文本或未授权附件的访问入口；编号直访同样执行权限校验。同人可以派发多个任务。
3. 本部门处置账号记录进展、上传跟进附件、保存跟进或提交处理结果。提交后进入「中心待审核」，显示本轮 submitted_at 起点；不自动通过、办结事件或关闭预警。
4. 中心填写审核理由，退回补充或通过关闭任务。退回后可再次跟进、提交，所有轮次留存。退回不改变原任务期限；后续 27 号任务再实现责任阶段的超期提示。
5. 通过时仅办结明确勾选的本任务关联有效事件，可以不选事件而只关闭任务。不会默认办结该人员全部事件。事件各来源同步办结，后续合并到已办结有效事件的来源继承状态。累计风险仍包含这些有效事件；预警须另行填写结论关闭。
6. 附件上传后默认私有，只有上传者可下载；在派发或跟进时明确选入任务后才向任务授权范围开放。每次最多选择 20 个附件，单附件不超过 5MB；通过受控下载提供，不直接公开文件路径。

归档变化导致关联事件已迁出或无效时，当前关闭审核会拒绝继续沿用关系；28 号任务的显式暂停与重新确认流程仍按原计划实施。

## API 与一致性

所有写操作需要登录及 CSRF；预警研判、任务跟进/审核、配置修改带 version。过期版本或重复处置返回 409。写操作与既有录入、归档、规则重算共用 intake 事务锁，审核、状态、授权及审计写入在同一事务内完成。

| 接口 | 用途 |
|---|---|
| `GET /api/cases/alerts` | `level,name,keyword,source,departmentId,from,to,state,backlog,page,size`；时间为生成时间，首尾均包含，返回 items/total |
| `GET /api/cases/alerts/{id}` | 本次快照、当前风险、新增标记及研判历史 |
| `POST /api/cases/alerts/{id}/reviews` | version、conclusion、close；close=false 只记录研判 |
| `GET/PUT /api/cases/settings` | backlogDays、version |
| `POST /api/cases/alerts/{id}/tasks` | version 为预警版本；personId、eventIds、departmentId、deadline、title、instruction、contact、summary、attachmentIds |
| `GET /api/cases/tasks` | state、page、size；返回权限内 items/total |
| `GET /api/cases/tasks/{id}` | 派发快照、授权字段、附件元数据及每轮历史 |
| `POST /api/cases/tasks/{id}/progress` | version、content、submit、attachmentIds |
| `POST /api/cases/tasks/{id}/reviews` | version、decision（RETURN/CLOSE）、reason、completeEventIds；默认空列表 |
| `POST /api/cases/attachments` | multipart 的 file；返回 id/fileName |
| `GET /api/cases/attachments/{id}` | 权限内附件下载 |

期限使用 ISO 本地时间，按 Asia/Shanghai 解释。预警和任务页默认每页 20 条，最多 100 条。V14 新增预警、研判、任务、关联事件、每轮历史及附件表，并为有效事件增加独立办结状态。

## 验证与审查（2026-10-18）

- 使用本机 MySQL 8.0.46 新建隔离库 governance_cases_final，后端 8081、前端 5174，不连接演示库；迁移与演示初始化真实执行。
- Maven verify 包含 3 项可控时钟测试，覆盖七天阈值前一秒/正好到期、配置阈值、已研判/关闭排除和重复计算。为避免占用演示服务 JAR，临时 POM 仅替换 build.directory 为 .local/cases-build，源码、依赖与插件不变。
- 7 项新增 API 场景覆盖预警生成/更新/关闭再触发、低风险再触发、过滤、配置、版本冲突、任务分页、授权快照、附件隔离、进展、提交退回再提交、明确事件办结及风险独立。
- 1 项完整浏览器场景覆盖中心研判、上传选择授权附件、派发、部门跟进提交、退回补充、再提交、中心勾选事件办结。
- 1 项规则后台重算场景验证相同规则不误标依据、规则升级触发已关闭预警、最后恢复原规则。
- code-review 两路审查：Standards 的任务分页与版本元数据误标问题、Spec 的低风险新事件再次触发问题均已修复，已补充回归并复核无新增问题。

最终验证：全量 Playwright 67 项通过（42.9 秒）；Maven verify 的 3 项时钟测试及编译打包通过；前端 npm run build（含 vue-tsc 类型检查）通过，仅有既有产物大小提示。本项不替代尚未完成的 Docker 交付、超期、统计、导出、跨业务历史和规模验收任务。
